# Checks and fixtures

Use focused checks relevant to a change, plus an actual Open/edit/Undo/save/reopen workflow for visible UI changes. Keep generated data and reports in ignored directories. The check executables are custom scenario runners; `dotnet test` is not their entry point.

## Reproducible Core checks

Build the native worker and solution first. From the repository root:

```powershell
python scripts/generate_fixtures.py
python scripts/generate_failure_fixtures.py
dotnet run --no-build --project src/BuilderCrap/Builder.Checks -- . --primitives-only
dotnet run --no-build --project src/BuilderCrap/Builder.Checks -- . --construction-only
```

The primitive checks cover the nine shapes, preview/Apply/Cancel, history, native Save and STL/3MF reopening. Construction checks cover split/booleans and selection ownership using the original base fixtures. These are shared Core scenarios, not native desktop-input tests. Some older modes write to fixed dated paths beneath `.local/evidence/`; use a disposable checkout or preserve existing output before rerunning.

The small files in `fixtures/generated` and `fixtures/failures` are original synthetic inputs generated by the included scripts. They contain no Microsoft assets or downloaded real models. Regenerating them is safe in this source checkout. The manifest records their hashes and intended dimensions/topology.

## Independent readers

Use an isolated environment if you want the Python geometry readers:

```powershell
python -m venv .local/verification-venv
.local/verification-venv/Scripts/python.exe -m pip install -r tools/verification-requirements.txt
.local/verification-venv/Scripts/python.exe scripts/verify_fixtures.py
```

The extra `verify_*_outputs.py` helpers read saved output independently from Builder assemblies. Their dated output locations reflect the original feature scenarios; generating the matching inputs/output is required. They are not assertions that old reports are included or that all modes have been rerun in this checkout.

## Other scenario runners

| Runner | Purpose / prerequisites |
|---|---|
| `Builder.Checks` | Core checks; use one focused mode. `generate_fixtures.py --help` lists additional synthetic input modes. |
| `Builder.Desktop.Checks` | Isolated WPF controls/routed events/software renders, not real mouse input or OS file dialogs. |
| `Builder.Mcp.Checks` | Real SDK subprocess/pipe protocol checks; requires the matching generated synthetic fixture tree and built Debug server. |
| Optional benchmark/trace projects | Historical diagnostic tools outside the normal solution; their recorded inputs/binaries are not shipped. |

The combined no-flag checks and several later feature modes assume a larger historical `.local` fixture tree. This public export retains their source but deliberately omits private evidence, captured binaries and downloaded real-part fixtures. They are not the fresh-checkout quick checks above.

Desktop's ordinary smoke entry point is `--normal-workflow-only --evidence-root <fresh-directory>`. It also requires its document-navigation fixture tree. Do not substitute `--v1-usability-only`: it includes accessibility/scaled-render tests. Accessibility/DPI testing and Windows settings changes are outside routine verification.

The v1 printing-job runner additionally expects locally obtained Prusa models with provenance/license records. Those third-party test assets are not bundled. Generate only the intended synthetic modes or supply appropriately licensed inputs rather than copying a research workspace into Git.

## Native editing

On a normal Windows desktop, open a generated model in explicit mm; preview/cancel a move; repeat and Apply; Undo/Redo; Save to a new 3MF; reopen it and verify the expected dimensions/placement. Preserve a dirty scene on cancelled file/tool operations. Do not equate a passing isolated WPF scenario with this real-input workflow.
